## Contract reconciliation before F2 network work

- The OpenAPI `AvailabilityRequest` describes `stay` plus `occupancy` and an optional `propertyId`, while the actual validator requires flat `property`, `checkIn`, `checkOut`, `occupancy`. The quote route currently returns the same direct serializer as availability, not the OpenAPI's generic `data`/`meta` placeholder. Reconcile documentation with the accepted implementation before building a client; do not invent response fields.
- The OpenAPI hold header allows up to 200 characters, while the actual handler accepts 8–128 and overrides any body `idempotencyKey` with the header. This is a future contract reconciliation, not a reason to wire holds now.
- Public hotel reads depend on trusted host resolution, active `HOTEL_BOOKING`, current property/room/rate/policy publication approval, and a separate operational gate. A visual preview or `isActive` alone is not publication authorization. Availability and quote remain read-only.

## Missing owner-approved inputs

- Official Hotel Damoon logo; verified hotel, lobby, room, and gallery photography; media ownership and approved alt text/order.
- Approved Persian room names/descriptions, capacities/amenity claims, property/about copy, public policies and cancellation language, and any actual nightly prices. Conceptual assets must remain labeled as such until replaced and published through the trusted mechanism.
- A backend public room/gallery representation with approved image metadata and localized content; the current search serializer does not supply those fields. The UI also needs a validated adult/child/child-age composition before a search request.

No production API, database, hold, payment, or deployment is part of this handoff.
