# Hotel CMS v2 integration

The Persian RTL Hotel CMS is available at `/{locale}/dashboard/hotel-website`. Tenant admins and managers see the entry only when their current organization has an active `HOTEL_WEBSITE` capability. A server-rendered property picker establishes the organization/property scope; platform administrators can select an eligible Hotel organization. The property editor is at `/{locale}/dashboard/hotel-website/{organizationId}/{propertyId}`.

The server page checks the active persisted user, Hotel vertical, active `HOTEL_WEBSITE` grant with `enabledAt`, active organization membership and role, and active property. These checks only control page access and scope. Every read or mutation is still authorized by the C1B1 management service, which rechecks current membership, capability, organization/property ownership, publication state, independent review, and current image eligibility.

The browser adapter uses the C1B1 routes under `/api/organizations/{organizationId}/hotels/{propertyId}/website`: `GET/POST /revisions`, `GET /revisions/{revisionId}/preview?locale=fa|en|ar`, `POST /revisions/{revisionId}/submit`, `POST /revisions/{revisionId}/review`, `POST /revisions/{revisionId}/publish`, `POST /publications/{publicationId}/revoke`, and `GET /history`. It sends same-origin credentials, `cache: no-store`, JSON mutation bodies and an `Idempotency-Key` for each mutation. The key is reused after transport, unreadable-body, or HTTP failures and cleared after a readable successful response.

Managers can create drafts and submit them for review. Admins and platform super-admins can review, publish, and revoke. C1B1 prevents self-approval and remains the authorization authority; client role props only hide unavailable controls. Preview responses are marked `PREVIEW` and are never routed through the C1B2 public reader. Publishing does not override the default-off `HOTEL_WEBSITE_PUBLIC_OPERATIONAL_ENABLED` rollout switch, and it does not enable `HOTEL_BOOKING`.

The CMS currently accepts IDs for already existing eligible tenant images; it does not upload or choose media. The backend validates image ownership, PUBLIC access, MIME type, serving URL, property/room scope and revision at each relevant workflow stage. The existing C1B1 revoke-before-republish gap remains visible in the UI. No database or frontend-preview workspace was changed by this integration.
