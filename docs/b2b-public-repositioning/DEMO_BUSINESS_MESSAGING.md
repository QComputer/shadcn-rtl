# Demo Business Messaging

This document defines the messaging for demo businesses shown on the public B2B homepage and portfolio pages.

## Demo Business Labels

All demo businesses must be explicitly labeled to avoid confusion with real tenants:

```
نمونه نمایشی فروشگاه
نمونه نمایشی رستوران
نمونه نمایشی داروخانه
نمونه نمایشی مطب
نمونه نمایشی مرکز خدماتی
```

## Demo Business Definitions

### 1. نمونه نمایشی فروشگاه
**Name:** فروشگاه نمونه
**Description:** دموی کامل فروشگاه اینترنتی با محصولات، دسته‌بندی و سبد خرید.
**Key features shown:**
- محصولات و دسته‌بندی
- سبد خرید و پرداخت
- پیگیری سفارش
- مدیریت موجودی

### 2. نمونه نمایشی رستوران
**Name:** رستوران نمونه
**Description:** دموی رستوران با منو دیجیتال، سفارش آنلاین و رزرو میز.
**Key features shown:**
- منو دیجیتال
- سفارش آنلاین
- رزرو میز
- مدیریت سفارش‌هایplantation

### 3. نمونه نمایشی داروخانه
**Name:** داروخانه نمونه
**Description:** دموی داروخانه با درخواست دارو، نوبت‌دهی و اطلاع‌رسانی.
**Key features shown:**
- کاتالوگ محصولات
- درخواست دارو
- نوبت‌دهی
- اطلاع‌رسانی موجودی

### 4. نمونه نمایشی مطب
**Name:** مطب نمونه
**Description:** دموی مطب پزشکی با نوبت‌دهی آنلاین و مدیریت قرارها.
**Key features shown:**
- نوبت‌دهی آنلاین
- مدیریت پرونده
- یادآوری نوبت
- گزارش درمان

### 5. نمونه نمایشی مرکز خدماتی
**Name:** مرکز خدماتی نمونه
**Description:** دموی مرکز خدماتی با درخواست سرویس، کارکنان و پیگیری.
**Key features shown:**
- درخواست سرویس
- مدیریت کارکنان
- پیگیری وضعیت
- اطلاع‌رسانی مشتری

## Demo CTA Examples

- مشاهده دموی کسب‌وکار
- دیدن پنل مدیریت این سناریو
- درخواست راه‌اندازی مشابه

## Demo Rules

- Demo names must clearly indicate demo/sample
- Demo businesses must not use real customer data
- Demo pages must be allowed in public demo portfolio
- Real tenant data must not appear in demo listing
- Demo APIs must not expose all organizations
- Demo seed must be idempotent

## Messaging Rules

- All demo copy must include the word "نمونه نمایشی"
- Demo pages must have clear "Demo" badges
- Demo CTAs must differentiate from real tenant CTAs
- Demo data must be clearly fictional
