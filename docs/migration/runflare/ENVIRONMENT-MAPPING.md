# Runflare environment mapping (R6.1)

**Scope:** read-only source/configuration inspection. No environment values, private configuration files, or dump contents were read. This maps the application contract to the target facts supplied by the owner; it does not establish that a Runflare deployment is configured or working.

## Confidence labels

- **CONFIRMED — source:** directly visible in tracked application/configuration source reviewed in this checkout.
- **OWNER-CONFIRMED — target:** target fact supplied by the project owner; not independently checked in Runflare.
- **UNVERIFIED runtime:** requires a deployed-runtime probe or provider confirmation.
- **INFERRED:** operational conclusion from source behavior, pending an owner/provider check.
- **BLOCKED:** required implementation, fact, or acceptance evidence is missing.

| Tenant model | **CONFIRMED — source:** one Next.js application with organization-scoped data and a single configured Prisma client; custom-domain tenancy resolves into that same app/database. | One application/service can serve multiple tenants; no per-tenant service/database mapping is implied. Enforce tenant checks in the app and verify host-to-tenant routing after proxy cutover. |
| Request model | **CONFIRMED — source:** Next App Router has 336 `route.ts`/`route.tsx` handlers and one file with a `use server` directive under `app/`; `proxy.ts` handles host, locale, and custom-domain rewrites. | Node server rendering, route handlers, and the Next 16 proxy are core requirements. ## Owner decisions required before environment provisioning

1. Confirm target public platform origin, proxy/TLS owner, and which custom-domain flows Runflare will support.
2. Choose a production PostgreSQL driver/URL contract and provide separate secret-store entries for runtime and direct maintenance connections.
3. Confirm the proposed `/disk/media` production adapter and its disk backup/restore and replica policy. Retain a provider-neutral seam for future S3; no new S3 service is required in this milestone.
4. List periodic jobs and define Runflare trigger, authentication, retry, concurrency, and observability contracts.
5. Choose shared rate-limit and Next cache strategy if the service will run more than one instance.
6. Decide which optional external integrations remain disabled at first cutover; provision and validate credentials only for those enabled.
