It does not connect to PostgreSQL or Blob, execute commands, read media bytes, transfer data, or write a database. Do not interpret a generated plan as restore authorization or target acceptance.

## Media plan

Run `node scripts/migration/runflare/plan.mjs --dry-run --kind media --input <sanitized-reference-and-object-metadata-json>`. Reference items may use `key`, `storageKey`, `url`, `path`, or `filename`; object metadata may use `key`, `pathname`, `url`, or `filename`. Include only safe identifiers, tenant IDs, reference family, public/private classification, byte counts, and SHA-256 values when already known. Do not include credentials, raw DB rows, customer fields, or signed URLs. URL query strings are discarded and `/uploads/` and `public/` aliases are normalized as relative keys.

The planner sorts entries and emits a manifest digest. It joins normalized DB references to supplied Blob metadata and reports planned object count/bytes, adapter-compatible target key, tenant, access class, reference count/families, source bytes, expected bytes/checksum, and blockers. Ordinary upload assets map to `tenants/<organizationId>/uploads/<filename>`. Existing accepted `creative-studio`, `tenants`, and `retail-payment` namespaces are retained when their organization segment matches the owner; target-key collisions are blocked. Backslashes and percent escapes are rejected, including percent-encoded traversal. Missing ownership, invalid/traversal paths, cross-tenant ownership, public/private ambiguity, conflicting aliases, duplicate Blob keys, missing object metadata, unreferenced objects, and known size/checksum mismatches are blocked. It performs no download, copy, delete, or DB reference update. A metadata-only plan cannot prove object contents or source completeness.

The captured R6.1 source metadata remains in the operator-controlled local artifact `C:/Users/disso/.codex/artifacts/runflare-r61-20261024/source-metadata.json`; this planner neither opens nor prints it. R6.1 recorded 90 Blob objects / 65,910,202 bytes at provider aggregate level, while object-level listing was unavailable. Provide a separately authorized, sanitized object metadata export before claiming inventory completeness. Keep the R6.1 ledger baseline intact, including all four historical rolled-back entries.

## Validation and limits

Run the focused unit suite with `node --test tests/unit/runflare-migration-tooling.test.mjs`. It covers source/target identity mismatch, ledger baseline drift, incomplete target and extension proof, `pg_session_jwt` portability gating, preservation of all nine Neon Auth table counts, no-execute behavior, tenant/access collisions, traversal rejection, alias normalization, checksum metadata, and deterministic output. These are pure planner checks; they are not PostgreSQL CLI, provider, backup, archive, catalog dependency, restore, or media-transfer evidence. Until root SQL-catalog review supplies verified extension dependencies and target capability, keep the planner blocked or use the target-supported `preserve-native` strategy.
